# 語音轉錄與摘要系統

把 YouTube 影片、上傳的音訊、或資料夾裡新出現的錄音檔，**轉成文字 → 校對 → 依指定「人格」產出心得**。轉錄與 AI 處理都在本機完成（Whisper + LM Studio），不上傳雲端。

## 緣起

起因很單純：我不想把別人轉來的一堆 YouTube 影片一支支看完再寫心得，所以做了這個工具。之後延伸想到兩個應用方向——**客服錄音整理**、**總機錄音檔判讀（分析來電訊息）**——並以測試資料驗證過流程可行。

這是我自己發想與開發的個人專案，**不是公司指派的工具，也沒有在公司實際運行**。

## 功能

| 功能 | 說明 |
|------|------|
| YouTube | 優先抓官方字幕；沒有字幕才下載音訊並用 Whisper 轉錄 |
| 上傳音訊 | 手動上傳 mp3／wav／m4a／aac／flac 等 |
| 資料夾監控 | 排程定時掃描指定資料夾，新檔案自動轉錄並產出報告 |
| 多人格 | 同一份逐字稿可套用不同人格（提示詞）產出不同風格的心得 |
| 媒體庫 | 瀏覽、檢視、刪除歷史轉錄與報告 |

## 設計重點

- **同一來源只轉錄一次**：以 URL 或檔案 MD5 當唯一鍵，逐字稿與校對結果存在媒體主表；換人格只重跑最後一步，不重轉錄。這是從 v4（每次都重轉）改版時最主要的痛點。
- **雙工序處理**：先「校對」（低溫度、不改原意）修正語音辨識錯字，再「產出心得」（高溫度、風格化）。
- **長文分段**：本地 7B 模型 context 有限，長逐字稿會切成約 1500 字、帶重疊的片段，先摘要再合併，避免被截斷。
- **排程設定存資料庫**：掃描間隔、監控資料夾、套用人格都能在介面調整，重啟後自動恢復。
- **GPU 自動偵測**：有 CUDA 用 GPU，否則退回 CPU。

## 應用情境：總機／客服錄音判讀

資料夾監控模式可以直接指到錄音檔目錄，搭配針對來電場景撰寫的人格提示詞（例如「整理來電者需求、情緒與待辦」），把每通錄音變成結構化的摘要。我用測試錄音驗證過這個流程；程式本身沒有專屬的客服模組，是靠人格提示詞達成。

## 快速開始

```bash
git clone https://github.com/WeiMingYu/voice-transcribe-summary.git
cd voice-transcribe-summary
python -m venv venv && venv\Scripts\activate      # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
# 另需安裝 ffmpeg 並加入 PATH；並啟動 LM Studio（預設 localhost:1234）載入任一對話模型
python -m streamlit run app.py
```

資料庫（`reports.db`）會在第一次啟動時自動建立，並內建一個預設人格。

## 專案結構

```
app.py              主程式：側欄人格管理＋四個分頁
core/
  transcribe.py     Whisper 轉錄、YouTube 字幕／音訊下載、MD5
  ai_process.py     校對 + 分段摘要 + 產出心得
  scheduler.py      APScheduler 資料夾掃描
pages/              YouTube／上傳／資料夾監控／媒體庫 四個分頁
database/db.py      SQLite 資料表與操作（5 張表）
docs/DEV_NOTE.md    開發記錄
```

## 已知限制

- 只在我自己的電腦（NVIDIA 3060 8GB）上測過，Whisper 使用 small 模型。
- 沒有自動化測試，靠實機驗證。
- 沒有使用者登入與權限控管，定位是單機個人工具。
- YouTube 下載功能請自行確認並遵守平台服務條款與影片著作權。
- 校對與摘要品質取決於你載入的本地模型；我用的是 7B 級模型，長文仍可能失真，重要內容請人工覆核。
- 語音辨識沒有說話者分離（無法區分誰在說話），這對通話錄音的分析是限制。
- 沒有針對錄音檔個資（來電者姓名、電話）做遮蔽。若用於真實通話錄音，需自行處理合規與個資問題。
